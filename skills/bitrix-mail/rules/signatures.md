# Подписи main.mail.form — Since main 26.1000

Форма получает подписи через `Bitrix\Main\Mail\Sender::prepareUserMailboxesWithSignatures()`. Метод отправляет D7-событие main:OnMailSenderListBuild с userId и массивом senders. Каждый отправитель содержит key (форматированная строка формы), email, name, mailboxId.

Обработчик возвращает `EventResult::SUCCESS` с параметрами:

- signatures: список `{id, signature, scope, senderTexts}`; id положительный, signature — HTML подписи, scope — shared либо личная область, senderTexts — подмена HTML по ключу отправителя;
- senders: карта `key => {availableSignatureIds: int[], selectedSignatureId: int|null}`. Ключи должны быть взяты из входных senders; неизвестные игнорируются.

Ядро объединяет доступные ID без повторов; первая непустая выбранная подпись побеждает. Результат кешируется на пользователя в пределах хита. Обработчик должен проверить собственные права и вернуть только доступные этому userId подписи. Если обработчик отсутствует, форма получает пустые списки. Не считай, что установленный модуль mail любой версии уже поставляет эти данные.

На старом main этого события нет: используй механизм подписей конкретной версии main.mail.form / mail; не регистрируй обработчик в надежде, что старое ядро его вызовет. Этот контракт относится к подписи **текста письма**, а не криптографической подписи параметров или настройке SMTP.
