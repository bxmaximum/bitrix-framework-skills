# Границы DI

| Контекст | Как передать зависимость |
| --- | --- |
| Прикладной сервис | Конструктор; ServiceLocator собирает конкретный класс по типам параметров |
| Action контроллера | Параметр с типом конкретного класса; интерфейс автоматически не разрешается |
| Конструктор контроллера | Не добавляй зависимости: движок передаёт Request |
| Консольная команда | **Since main 26.900** — конструктор через ServiceLocator. Раньше — `get()` внутри `execute()` |
| Обработчик события | Получи сервис внутри обработчика |
| Messenger receiver | Конструктор; экземпляр собирает ServiceLocator |

В доменном коде не обращайся к контейнеру. Для интерфейса или скалярных аргументов настрой `services`. Конкретный класс, которому нужны только другие классы, обычно не требует регистрации.

Запись только с `className` для конкретного класса отключает autowire: ядро делает `new $class()` без зависимостей. Используй `constructor`, `constructorParams` или убери ненужную регистрацию. Версии и примеры — `bitrix-service-locator`.

Консольное правило зависит от версии: в main 26.1000.0 `main/cli/bitrix.php` вызывает `ServiceLocator::getInstance()->get($commandClass)`, в main 26.600.0 — `new $commandClass()`.
