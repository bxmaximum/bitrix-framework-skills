# Кеширование

Baseline: main 23.0+ · Verified: main 26.1000.0

Перед PHP-кодом прочитай `bitrix-framework`, если ещё не читал его в этой задаче.
В таблице выбери только нужный `rules/*.md`; пути относительны каталогу скилла.


| Задача | Читать |
| --- | --- |
| Движок, серверы, `cache_flags`, отказ кеша | `rules/engine-config.md` |
| Кеш данных, ключи, теги и сброс | `rules/data-tags.md` |
| Управляемый кеш, кеш результата компонента | `rules/managed-components.md` |

Для кеша запросов ORM используй `bitrix-orm`; для всей страницы — `bitrix-performance`.

## Основные правила

- Ключ учитывает все входы, влияющие на результат, включая сайт, язык и права пользователя.
- `clearByTag()` очищает каталоги: выделяй своим данным отдельный путь кеша.
- Прямая запись SQL требует `XxxTable::cleanCache()`; автоматических тегов `ORM_<TABLE>` нет.
- Движок должен соответствовать текущему окружению. Исправление кеша не требует смены инфраструктуры.

## Проверка

- [ ] Ключ кеша учитывает каждый вход; пустой/ошибочный результат вызывает `abort*Cache()`.
- [ ] Каждый тег сбрасывается при изменении соответствующих данных.
- [ ] Область тегов использует тот же каталог, что и кеш данных.
- [ ] После прямой записи SQL кеш ORM очищается через `cleanCache()`.
- [ ] Движок совместим с текущим окружением; смена инфраструктуры не требуется для обычной правки кеша. `sid` уникален для копии сайта.
