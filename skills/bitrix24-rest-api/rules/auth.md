# Авторизация и scopes

## Выбор интеграции

| Задача | Вариант | Авторизация |
| --- | --- | --- |
| Скрипт/синхронизация одного портала без интерфейса | Входящий вебхук | `https://{host}/rest/{userId}/{code}/{method}` |
| Реакция на изменения одного портала без приложения | Исходящий вебхук | обработчик получает `auth[application_token]` |
| Страница Битрикс24 без своего сервера | Статическое локальное приложение, ZIP HTML/JS | авторизация iframe через BX24.js/b24jssdk; без приёма событий |
| Страница, встройки, события, сервер одного портала | Серверное локальное приложение с интерфейсом | упрощённый OAuth, токены приходят POST на страницу |
| Фоновая синхронизация и события одного портала | Серверное локальное приложение без интерфейса | токены приходят POST обработчику установки |
| Много порталов, Маркет | Тиражное приложение, ключи партнёрского кабинета | полный OAuth 2.0 |

- Вебхук действует от создателя в пределах выбранных scopes. Методы с контекстом приложения (`event.bind`, `placement.*`, часть телефонии и ботов) недоступны и отвечают `WRONG_AUTH_TYPE`.
- Вебхуки и локальные приложения создаются в «Ресурсах разработчика»; в коробке путь `/devops/`, положение пункта облака зависит от интерфейса. Приложению выдаются `client_id` (`local.…`) и `client_secret`.
- Идентификатор портала — `member_id`, сохраняется при смене домена. Используй его ключом хранения токенов и `application_token`.

## Полный OAuth 2.0

1. Перенаправь пользователя на `https://{portal}/oauth/authorize/?client_id=…&state=…`. `redirect_uri` берётся из настроек приложения, не из запроса. Сверь `state` в callback с сохранённым значением.
2. Callback получает `code` (действует 30 секунд), `state`, `domain`, `member_id`, `server_domain`.
3. На сервере: `GET https://{server_domain}/oauth/token/?grant_type=authorization_code&client_id=…&client_secret=…&code=…`.
4. Ответ: `access_token` (1 час), `refresh_token` (180 дней), база `client_endpoint`, `server_endpoint`, `member_id`, `scope`.

Вызывай `{client_endpoint}{method}` с токеном в `auth` тела JSON; query string допустим, но раскрывает токен в URL.

## Обновление токенов

- После `expired_token` (401) обнови пару через `grant_type=refresh_token&client_id=…&client_secret=…&refresh_token=…` на сервере авторизации и повтори вызов один раз. Замени сохранённую пару целиком.
- Не обновляй перед каждым вызовом и по частому таймеру: сервер блокирует таких клиентов. Неактивную интеграцию обновляй не реже раза в 180 дней.
- Сериализуй обновление по `member_id`, чтобы параллельные обработчики не использовали один refresh-токен одновременно.
- Обращайся прямо к серверу авторизации, не `{portal}/oauth/token/`: коробка может не проксировать вызов. Адрес бери из `server_endpoint`/`server_domain`, не фиксируй `oauth.bitrix.info`. Коробка RU/СНГ использует `oauth.bitrix24.tech` (**Since rest 26.200\***); на старом ядре опция `rest/oauth_server`, по умолчанию `oauth.bitrix.info`.
- Передавай `client_secret` только серверу авторизации, не порталу и браузеру.
- Ошибки: `invalid_grant` — истёк refresh-токен, повтори полный OAuth; `invalid_client` — неверные ключи/нет установки; `PAYMENT_REQUIRED` — платное приложение не оплачено, токены до оплаты не выдаются.

## Приложение в iframe и установка

- Страница приложения/встройки получает POST `AUTH_ID`, `AUTH_EXPIRES`, `REFRESH_ID`, `APPLICATION_TOKEN`, `member_id`, `status`, `PLACEMENT`, `PLACEMENT_OPTIONS`. В query string приходят `DOMAIN`, `PROTOCOL`, `LANG`, `APP_SID`.
- POST `status` информационный. Доверенный статус бери через `app.info` на сервере авторизации.
- Приложению без интерфейса задай «Путь для первоначальной установки». После установки туда приходит POST `auth[...]` (`form-urlencoded`); сохрани `refresh_token` и `application_token`.
- Если включено «Приложение завершает установку самостоятельно», события и встройки не активны до `BX24.installFinish()` либо `installFinish()` b24jssdk.

## Разрешения scopes

- Бери scope из страницы метода. Встройке нужны `placement` и scope инструмента.
- `scope` возвращает выданные scopes; `{"full": true}` — все доступные на портале.
- `method.get {"name": "…"}` возвращает `isExisting`/`isAvailable` для текущих реквизитов. Имя передавай в нижнем регистре.
- Недостаток scope проявляется как `insufficient_scope` (401) либо `ERROR_METHOD_NOT_FOUND` (404). Последний код также требует проверки имени, версии API и установленных модулей.
