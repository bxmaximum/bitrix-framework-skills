# Лимиты, ошибки и повторы

## Лимиты облака

| Ограничение | Значение | Ошибка |
| --- | --- | --- |
| Частота HTTP-запросов, общий счётчик портала с учётом IP | Enterprise: убывает на 5/с, блокировка выше 250; прочие: 2/с и 50 | `QUERY_LIMIT_EXCEEDED`, HTTP 503 |
| Время метода для приложения/вебхука | сумма по 10 минутным корзинам, порог задаёт портал | `OPERATION_TIME_LIMIT`, HTTP 429 |
| Один запрос | 60 секунд, затем таймаут | — |

- Приложения с одного IP, работающие с одним порталом, делят счётчик частоты. Не запускай параллельные потоки ради обхода лимита.
- Batch — один HTTP-запрос, но время каждого вложенного метода учитывается отдельно.
- В коробке частоту инфраструктура облака не ограничивает, лимитер суммарного времени выключен по умолчанию (`rules/on-premise.md`).

## Лимит одного SQL-запроса

Официальная облачная документация на 30.10.2026 описывает отдельный лимит SQL-запроса внутри REST-метода. REST 3.0 возвращает `BITRIX_REST_V3_EXCEPTION_LIMITER_QUERYTIMELIMITEXCEPTION`, HTTP 503 и `Retry-After`; классические Engine-контроллеры — HTTP 400 без этого заголовка. Уменьши выборку и сложность фильтра; повтор планируй не раньше `Retry-After`, а запись повторяй только идемпотентно.

Это отдельное ограничение, не `QUERY_LIMIT_EXCEEDED` и не `OPERATION_TIME_LIMIT`. По облачной документации нельзя заключать, что оно реализовано в конкретной коробке: в проверенном исходнике rest 26.1100 реализация этого лимитера не найдена. Источник: [REST API Limits](https://apidocs.bitrix24.com/settings/performance/limits.html#sql-query-time-limit).

## Распознавание ошибки

- Классический ответ: `{"error": "CODE", "error_description": "…"}`. `error` бывает пустой строкой: тогда смысл только в описании, например `400` + `Not found`. Проверяй `array_key_exists('error', …)`, не истинность значения.
- Классический batch: HTTP 200, ошибки по ключам команд в `result.result_error`.
- REST 3.0: `{"error": {"code", "message", "validation"}}` (`rules/rest-v3.md`).
- Ветвись по коду, не по локализованному изменяемому `error_description`.
- Один код бывает системным и прикладным; проверяй также HTTP-статус и описание контекста (`ACCESS_DENIED`: 401 — системный отказ, 403 — правило метода).

## Действия по коду

| Код | Действие |
| --- | --- |
| `QUERY_LIMIT_EXCEEDED` | экспоненциальная задержка со случайным разбросом; отказ до выполнения, повтор записи безопасен |
| `OPERATION_TIME_LIMIT` | приостановить этот метод для приложения/вебхука до `time.operating_reset_at` последнего успеха; другие методы продолжают работать |
| `INTERNAL_SERVER_ERROR`, `ERROR_UNEXPECTED_ANSWER` | чтение повторить через несколько секунд; запись — только идемпотентно (`Idempotency-Key` REST3 либо проверка существования объекта) |
| `expired_token` | обновить токены (`rules/auth.md`), повторить один раз |
| `NO_AUTH_FOUND`, `INVALID_CREDENTIALS`, `invalid_token` | исправить реквизиты, без автоматического повтора |
| `insufficient_scope`, `ERROR_METHOD_NOT_FOUND` | проверить scope, имя, версию API и наличие модуля; без автоматического повтора |
| `INVALID_REQUEST` (`Https required`) | использовать `https://` |
| `ACCESS_DENIED` (401), `FEATURE_NOT_AVAILABLE_ON_CURRENT_PLAN` (403) | проверить доступность REST/тариф, сообщить администратору; повтор не исправляет доступ |
| `OVERLOAD_LIMIT` | ручная блокировка: прекратить вызовы, обратиться в поддержку |
| `user_access_error` | администратор выдаёт пользователю доступ к приложению |
| `PORTAL_DELETED` | публичная часть сайта закрыта |
| Ошибка метода (400/403) | исправить запрос; неизменённый повтор даст тот же результат |

`FEATURE_NOT_AVAILABLE_ON_CURRENT_PLAN` — облачный отказ Vibe+ (**Since rest 26.650**). На старой версии и для других отказов встречается `ACCESS_DENIED`. В свежем rest 26.1100 публичный код сохранён; перенос внутренних PHP-классов Vibe+ его не отменяет.

Записывай код, описание, HTTP-статус и имя метода. Не журналируй токены, код вебхука и `application_token`.

Клиент на ядерном HttpClient для PHP внутри коробки — `rules/php-client.md`. Для внешней интеграции используй HTTP-клиент своего приложения; PHP-ядро Битрикса ей не требуется.
