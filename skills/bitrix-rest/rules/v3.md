# Методы REST 3.0

**Since rest 26.200\***. На старом модуле: Engine + `restIntegration` (`rules/classic.md`); оба варианта работают параллельно. Клиентские URL, тело, batch и `Idempotency-Key`: `bitrix24-rest-api`, `rules/rest-v3.md`.

## Регистрация

`.settings.php` установленного модуля:

```php
return [
    'rest' => [
        'value' => [
            'defaultNamespace' => '\\Vendor\\Shop\\Infrastructure\\Rest\\Controller', // обязательно
            // 'namespaces' => ['\\Vendor\\Shop\\Rest\\Old'], // дополнительные пространства имён
            // 'routes' => ['alias' => 'vendor.shop.order.list'],
        ],
        'readonly' => true,
    ],
];
```

- Другие ключи: `controllerProvider` (наследник `Bitrix\Rest\V3\Schema\SchemaProvider`), `documentation`. Образцы: `rest/.settings.php`, `main/.settings.php`.
- Класс внутри этих пространств имён с базой `Bitrix\Rest\V3\Controller\RestController` становится контроллером. Методом API становится каждый публичный `*Action`, возвращающий наследника `Bitrix\Rest\V3\Interaction\Response\Response`.
- Имя: `<moduleId>.<путь класса после namespace в нижнем регистре, \\ заменяется точкой>.<action>`. `…\Controller\Order::listAction` модуля `vendor.shop` публикуется как `vendor.shop.order.list`. При переносе классов укажи новый `defaultNamespace`, сохранив старый в `namespaces`.
- Scopes метода: все префиксы имени до точек (`vendor`, `vendor.shop`, `vendor.shop.order`, …) и значения `#[Scope('x')]` действия. Достаточно одного разрешённого scope.
- Поиск кешируется по версии модуля и mtime `install/version.php`. После добавления действия обнови этот файл либо вызови `\Bitrix\Rest\V3\CacheManager::cleanAll()`. Только при разработке: глобальная `.settings.php` с `'rest' => ['value' => ['v3_cache_disabled' => true]]`.

## Контроллер на ORM

```php
namespace Vendor\Shop\Infrastructure\Rest\Dto;

use Bitrix\Rest\V3\Attribute\Filterable;
use Bitrix\Rest\V3\Attribute\OrmEntity;
use Bitrix\Rest\V3\Attribute\ResolvedBy;
use Bitrix\Rest\V3\Attribute\Sortable;
use Bitrix\Rest\V3\Dto\Dto;
use Vendor\Shop\Infrastructure\Rest\Controller\Order;
use Vendor\Shop\Model\OrderTable;

#[OrmEntity(OrderTable::class)]
#[ResolvedBy(Order::class)]
final class OrderDto extends Dto
{
    #[Filterable, Sortable]
    public ?int $id;

    #[Filterable]
    public ?string $statusId; // соответствует полю ORM STATUS_ID
}
```

```php
namespace Vendor\Shop\Infrastructure\Rest\Controller;

use Bitrix\Rest\V3\Attribute\DtoType;
use Bitrix\Rest\V3\Controller\GetOrmActionTrait;
use Bitrix\Rest\V3\Controller\ListOrmActionTrait;
use Bitrix\Rest\V3\Controller\RestController;
use Vendor\Shop\Infrastructure\Rest\Dto\OrderDto;

#[DtoType(OrderDto::class)]
final class Order extends RestController
{
    use ListOrmActionTrait; // vendor.shop.order.list
    use GetOrmActionTrait;  // vendor.shop.order.get
}
```

- Трейты: `List|Get|Add|Update|Delete|Tail|AggregateOrmActionTrait`. Образцы: `main/lib/Rest/V3/Controller/EventLog.php` и `main/lib/Rest/V3/Dto/EventLogDto.php`.
- Атрибуты свойств: `Filterable`, `Sortable`, `Editable`, `Required`, `Title`, `Description` и main `Validation\Rule\*` (`bitrix-validation`).
- **Since rest 26.600** без `select` список выбирает только скалярные поля DTO (раньше `*`). На старой версии задавай `select` явно.
- Действия трейтов `final` и сами не ограничивают строки по правам. Добавь фильтр после `...parent::getDefaultPreFilters()` (образец EventLog) либо собственное действие.

## Своё действие

```php
use Bitrix\Main\Validation\Rule\PositiveNumber;
use Bitrix\Rest\V3\Interaction\Request\Request;

final class CancelRequest extends Request
{
    #[PositiveNumber]
    public int $orderId;
}
```

```php
#[\Bitrix\Rest\V3\Attribute\Scope('vendor.shop.write')]
#[\Bitrix\Rest\V3\Attribute\NotIdempotent]
public function cancelAction(CancelRequest $request): \Bitrix\Rest\V3\Interaction\Response\UpdateResponse
{
    if (!$this->canCancel($request->orderId)) {
        throw new \Bitrix\Rest\V3\Exception\AccessDeniedException();
    }
    \Bitrix\Main\DI\ServiceLocator::getInstance()->get(OrderService::class)->cancel($request->orderId);

    return new \Bitrix\Rest\V3\Interaction\Response\UpdateResponse();
}
```

- Наследник `Request` заполняется из JSON. Без `#[DtoType]` контроллер падает с `ClassRequireAttributeException`. Конструктор контроллера не поддерживает DI (`bitrix-framework`).
- В `getDefaultPreFilters()` / `getDefaultPostFilters()` сохраняй `parent::`: он добавляет фильтр идемпотентности (**Since rest 26.600**). На старом модуле проверяй внешние ключи перед повторной записью.
- Не переобъявляй `$responseLanguage` / `getResponseLanguage()`: с 26.600 они типизированы, несовместимое объявление вызывает фатальную ошибку.

## Ошибки

- Бросай `Bitrix\Rest\V3\Exception\*` (`AccessDeniedException`, `EntityNotFoundException($id)`, …). Код ошибки получается из FQCN: `\\` заменяется `_`, буквы заглавные; HTTP-статус задаёт класс. Другие исключения превращаются в `InternalException` (500) и журналируются.
- Своя ошибка: наследник `RestException`, метод `getMessagePhraseCode()`, при необходимости `protected const STATUS = '409 Conflict'`; фраза — в lang-файле класса. Для ожидаемых ошибок используй `SkipWriteToLogException`.

Идемпотентность, перечисления, отложенный batch и ограничения атрибутов: `rules/v3-runtime.md`.
