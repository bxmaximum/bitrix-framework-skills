# Идемпотентность, перечисления и отложенный batch

**Since rest 26.600**

- Действия с `AddRequest`/`UpdateRequest`/`DeleteRequest` автоматически используют `Idempotency-Key`. Для других: `#[Idempotent(ttl: 3600)]`, отключение `#[NotIdempotent]` имеет приоритет. Сохраняются только ответы 200; при отказе хранилища действие выполняется без защиты. На старом модуле проверяй свой внешний ключ.
- `#[DynamicEnum(Provider::class)]` на свойстве DTO: провайдер реализует `Bitrix\Rest\V3\Dto\DynamicEnum\DynamicEnumProvider` (`getType()`, `getValues()`), создаётся через `new` без аргументов. При изменении данных вызывай `DynamicEnumRegistry::clear(Provider::class)`. На старой версии используй собственную валидацию допустимых значений.
- `rest.deferredbatch.*` выполняется очередью Messenger `rest.deferred_batch`; запусти обработчики (`bitrix-background-jobs`). В проверенной 26.1100 `OrmActionTrait` включает отложенный режим репозитория, а `OrmRepository` не навязывает обычный лимит 50 при отсутствии пагинации. Явные параметры страницы учитываются. В 26.650 списки оставались постраничными; на ней обходи страницы самостоятельно.
- В rest 26.650 конструктор `#[Enabled(...)]` ошибочно отвергал строковое имя провайдера (`!$provider instanceof …`). В проверенной 26.1100 ошибка сохраняется; проверяй доступность в действии.
