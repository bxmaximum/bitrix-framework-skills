# Архитектура модуля

Для нового модуля ориентируйся на актуальные `make:*` (`bitrix-console-commands`). Для существующего сохраняй принятую структуру и публичные контракты.

| Классы | Путь внутри `lib/` |
| --- | --- |
| Контроллеры и объекты запросов | `Infrastructure/Controller`, `Infrastructure/Controller/Request` |
| Агенты | `Infrastructure/Agent` |
| Сервисы, доступные другим модулям как PHP API | `Public/Service` |
| Внутренние сервисы | `Internals/Service` |
| ORM-классы `*Table` | `Internals/Model` |
| Внутренние интерфейсы | `Internals/Contract` (для репозиториев — `Internals/Contract/Repository`) |
| Публичные интерфейсы модуля | `Public/Contract` |
| Реализации репозиториев | `Internals/Repository` |
| Предметные объекты | `Internals/Entity` |

- Контроллер делегирует прикладной сценарий сервису. Для простой выборки сервис может обращаться напрямую к D7 ORM. Добавляй репозиторий по ТЗ или для составного либо повторяемого доступа к данным.
- Привязку интерфейса к реализации настраивай по `bitrix-service-locator`.
- Выделяй предметный объект, когда у него есть собственное поведение или правила состояния. Создавай каталоги по мере появления классов.
- Если в модуле несколько самостоятельных функций, группируй классы внутри слоя по функции. Например, `Infrastructure/Controller/Booking` и `Internals/Service/Booking`.
- У `make:tablet` папка по умолчанию — `Tablet/`. Для `Internals/Model` передай свой `--namespace`.
