# Безопасность

Baseline: main 23.0+ · Verified: main 26.1000.0

Перед PHP-кодом прочитай `bitrix-framework`, если ещё не читал его в этой задаче.
В таблице выбери только нужный `rules/*.md`; пути относительны каталогу скилла.

Общие правила (без суперглобальных массивов, сохранение стандартных фильтров, экранирование вывода) задаёт `bitrix-framework`.

| Задача | Читать |
| --- | --- |
| CSRF, экранирование, очистка HTML, ссылки, перенаправления и HTML-приёмники | `rules/csrf-xss.md` |
| SQL-инъекции (прямой SQL, ORM, `ExpressionField`), SSRF, локальные файлы, загрузки, настройки | `rules/sql-ssrf.md` |
| Права, `#[ActionAccess]`, области REST, JWT/JWK, шифрование, 2FA | `rules/jwt-crypto-access.md` |

## Обязательные правила

- Недоверенные данные: запросы, настройки из БД, импорты и REST. Тип и владелец сущности берутся из её записи БД, не из запроса.
- Всё, что становится структурой SQL (поля, операторы, функции, ключи `order`), проверяй по разрешённому списку независимо от источника.
- Экранируй для контекста вывода: HTML — `htmlspecialcharsbx()`, JS — `Json::encode()`, URL — через разрешённый список схем.
- Непроверенный пользовательский ввод не передаётся в `CFile::MakeFileArray()`, `file_get_contents()`, `unserialize()` и адреса перенаправления.
- `Authentication`/`Csrf` не проверяют права: проверяй доступ к объекту в каждом действии.
