# Alaio Vibecode

Платформа создаёт приложения Битрикс24 через собственный API. Вход — `GET https://vibecode.bitrix24.com/v1/me`, для порталов СНГ — `https://vibecode.bitrix24.tech/v1/me` (документация там на русском): возвращает доступные объекты, права ключа и инструкции. Ключ хранится в env проекта; не вставляй его в код, документацию и MCP-запросы.

## Выбор ключа

- `vibe_api_…` — личный ключ, действует от одного пользователя как вебхук; для встраивания в интерфейс не подходит.
- `vibe_app_…` — приложение с OAuth; пользователи работают со своими правами. Нужен для встроек и событий.
- `vibe_live_…` — управление ключами и порталами без доступа к данным.
- `READWRITE` — режим по умолчанию; `READONLY` отклоняет запись с 403 `WRITE_BLOCKED_READONLY_KEY`.

API преобразует имена полей и фильтры, собирает страницы до 5000 объектов (типовая страница REST — 50), выполняет batch и повторы временных ошибок. Дополнительно доступны серверы Black Hole с туннелем и сном после 60 минут простоя, подписки с повторной доставкой, модели `/v1/models`, `/v1/embeddings`, поиск `/v1/search`, хранилище и версии исходников.

Лимиты платформы могут меняться. Проверяй инструкции `/v1/me`, ответ 429 и `X-RateLimit-Limit`. Ранее опубликованные значения: 300 запросов/мин на ключ; поиск 60/мин; маршрутизатор ИИ 600/мин на ключ и 1500/мин на пользователя. Не используй их вместо фактических заголовков текущего ответа.

Для облака нужны платный тариф Битрикс24 и Vibe+. Серверы, тарифицируемые модели, поиск и агенты расходуют Vibe credits: 1 Ꝟ = 1 USD. При исчерпании бюджета платная операция отвечает 402; работа в пределах подписки продолжается. Расходующие кредиты вызовы выполняй только в согласованном объёме.

При утечке создай новый ключ и отключи старый. У каждого участника свой ключ. Для внутренних инструментов, ботов и ИИ без своего хостинга подходит Vibecode; для своей инфраструктуры, Маркета, собственного хранения токенов и неподключённой коробки используй обычное REST-приложение (`bitrix24-rest-api`).

## Коробка: `vibecodeconnector`

Перед PHP-изменениями один раз прочитай `bitrix-framework`. Проверено по исходникам модуля 26.900.0; функции ниже появились в более ранних версиях.

- Для установки beta требуется принять условия. Нужен включённый REST; используются `im` и `socialservices`. Одному лицензионному ключу соответствует одно подключение.
- Подключение в настройках регистрирует коробку в `vibecode.bitrix24.com`; для СНГ/неопределённого региона — `vibecode.bitrix24.tech`, сохраняет ключ сопряжения.
- Платформа вызывает действия модуля с `Authorization: Bearer <JWT>` и `CheckIncomingJwt`. Коробка должна быть доступна платформе. Личный API-ключ создаёт входящий вебхук пользователя, ключ приложения — персональное приложение коробки.
- `permission_source=vibecode` обходит ограничения портала на создание вебхуков/приложений; `portal` применяет их. Для RU/BY нужна подписка Маркета (`SUBSCRIPTION_REQUIRED`).
- Сначала отключи соединение через Disconnect, затем удаляй модуль. Пользователь добавляет подключённую коробку в Vibecode через «Подключить коробочный Битрикс24».
- **Since vibecodeconnector 26.400** каталог коробки может потребовать ручного включения; доступ проверяется для сотрудника, одной установки модуля недостаточно. На старой версии пользуйся прежним интерфейсом и проверкой доступа своего модуля.

## Проверка результата

- [ ] Ключ обладает минимальными правами; при отсутствии записи выбран `READONLY`.
- [ ] Секреты отсутствуют в репозитории, логах, скриншотах и документационном MCP.
- [ ] Проверены доступ к приложению, права на изменяемые данные и обработка ошибок.
- [ ] Тариф, лимиты и бюджет сверены перед расходующими кредиты операциями.
